# 凡塵修仙傳攻略頁

- 資料來源：https://k559610142-art.github.io/-username-.github.io-/ 的 `data/*.js`。
- `index.html` 是入口網站。**每新增一個頁面，都要在 `index.html` 的 `PAGES` 陣列加一筆**（href、icon、title、desc、tags），並在新頁面最上方放「← 回攻略首頁」連結到 index.html。
- **版本號**：`index.html` 標題「凡塵修仙傳攻略」字樣前方的 `#ver` 顯示攻略對應的遊戲版本號（例 `20261005BR`），讓使用者確認快取是否已刷新。**每次依遊戲更新修改攻略後，都要把它改成當時的遊戲版本號**（遊戲 `index.html` 裡 `<script src="data/xxx.js?v=版本">` 的 `?v=` 值）。
- **隱藏內容要保密**（遊戲作者要求）：青瀾島是隱藏地圖，攻略裡只以「？？？」顯示，不寫進入方式，也不提島上的任何人物與玩法；連搜尋索引都不能出現相關字詞。之後作者新增的隱藏地圖、隱藏人物比照辦理，詳細內容只在對話中給使用者看。
- 頁面不顯示抽選機率給玩家看。
- 頁面不寫資料來源細節（不要出現 data/、config-xxx.js 等檔名），連原始碼註解也不要。
- 每頁都要支援淺色／深色模式，連結用 `var(--link)`、強調字用 `var(--acct)`，文字對比度至少 3.5:1（不要用瀏覽器預設的藍色連結）。
- 經驗不顯示「每小時經驗」（依裝備而不同），也不寫地圖的經驗倍率；只顯示已套用地圖加倍後的單隻妖獸經驗。
  - 例外：`屬性與技能.html` 的「打怪推薦」分頁是依讀取的存檔（玩家自己的數值與裝備）計算，使用者要求顯示每張地圖每小時經驗與靈石。算法照遊戲的掛機估算移植，改動後要用遊戲本體的程式比對。
- `dmg.js` 是 `屬性與技能.html`「已學技能的傷害」用的平均傷害計算（屬性觸發、命中、破甲、屬性秘典、種族剋制）。裡面 `/*EX*/…/*EX*/` 之間的資料是產生出來的，不要手改：遊戲更新數值後執行 `node tools/build-dmg.js` 重新產生，再執行 `node tools/check-dmg.js` 用遊戲本體驗算（要顯示「不一致 0」）。`tools/game-vm.js` 會在 Node 裡載入遊戲本體，預設找 `../../idle-lineage-class/-username-.github.io-`（相對於 repo 根目錄），可用環境變數 `FANCHEN_GAME` 指定。
- `dmg.js` 的 `DMG.spacetime` 是亂星海時空秘境與靈界仙魔戰場共用的存活模擬（`EX.st`／`EX.xm`，頁面上是 `SZ.st`／`SZ.xm`；仙魔戰場的強度是範圍、每隻各擲；一秒一回合實際打 120 場，`屬性與技能.html` 的「試算」與「打怪推薦」分頁共用 `stCalc`／`stHtml`）。妖獸、技能、調息、丹藥、野外修士的數值都在產生出來的 `EX.st` 裡；2026-10-11 起模擬照遊戲線上戰鬥的整個回合流程移植（使用者要求，原本只算普攻、明顯低估）：技能格的仙法／宗門武學與靈寶閣武學（40% 施放、耗靈、增益進增益池）、普攻的各種特效、神器／職業技能、夥伴絕學、靈寵技能、各種護盾與保底、自動補血補靈、野外修士與暗殺者（含光暗互剋）；這些招式的數值在產生出來的 `EX.cb`，角色資料由頁面的 `stInput` 組。遊戲改了戰鬥規則（`combat.js` 的 `combatTick`／`fieldCombatRound`／`playerAttackTurn`、`monster.js`、`elements.js` 的 `resolveHit`、`artifact.js` 的 `castProcSkill`、`partner.js` 的 `partnerSkillTurn`、`beast-combat.js`、`gear.js` 的特效）要跟著改模擬，再執行 `node tools/check-spacetime.js`：它把同一份存檔交給遊戲實打、也交給頁面的 `analyze → hPlayer → stCalc → DMG.spacetime`，整條比對（要顯示「不一致 0」；全部跑完約 20～30 分鐘）。存活率對不上時加 `rate` 參數看每小時擊殺／倒下／吃藥是哪一項差。「時空秘境沒有通關」，頁面上一律叫存活機率。模擬比較花時間，使用者要求**只在讀取存檔時自動算一次**，之後改能力值、裝備或設定都要按「🌀 試算時空秘境」才重算（`stRun`／`stR`），不要改回每次重畫都算。
- `dmg.js` 的 `DMG.wboss` 是世界 Boss 的 30 回合傷害模擬（`屬性與技能.html`「試算」分頁的 `wbHtml`；資料在產生出來的 `EX.wb`）。算得快，所以每次重畫都重算，不用按鈕。遊戲改了世界 Boss 的回合規則（`world-boss.js` 的 `wbRound`／`wbBossStats`／`startWorldBossFight`）或 Boss 數值要跟著改，再執行 `node tools/check-wboss.js`（要顯示「不一致 0」，約 2 分鐘）。
- `tools/check-page.js` 用遊戲本體比對 `屬性與技能.html` 從存檔算出的數字（`analyze`／`hPlayer`：五項屬性、物理與術法攻擊、氣血、靈力、暴擊、連擊、防禦、魔防、閃避、命中、破甲）。**改了這頁的計算、或遊戲新增會加數值的來源（新仙法、新稱號、新系統）之後都要跑**，要顯示「不一致 0」。2026-10-11 用它抓到少收錄 20 招絕學（光環沒算到）和稱號、異火、仙法光環的防禦閃避沒算；防禦／閃避／魔防現在由 `dmg.js` 的 `attrs().bonus`（產生出來的資料）統一加總，不要再在 `hPlayer` 裡各來源手抄。
- 分享的短連結：`屬性與技能.html` 裡的 `SHARE_API` 是使用者自己架的短連結服務網址（程式在 `tools/share-worker/worker.js`，部署在 Cloudflare Workers＋KV，設定方式寫在該檔開頭）；留空時改用外面的短網址服務。改分享資料的格式時，`worker.js` 的格式檢查要一起看。
- `profile.js` 是全站共用的存檔暫存；新頁面要 `<script src="profile.js"></script>`，需要新的存檔欄位時加到它的 `KEEP` 清單。
- `site.js` 是全站共用的頂部搜尋與物品彈窗；新頁面要在 profile.js 後面加 `<script src="site.js"></script>`，內容要放在 `.wrap` 裡。
  - **新增或修改任何頁面的內容後，都要執行 `node tools/build-search.js` 重建 `search-index.js`**（用 Edge／Chrome 無頭模式把每頁跑一遍；頁面清單取自 `index.html` 的 `PAGES`）。
  - 物品資料在 `items.js`（「物品一覽」頁和彈窗共用）。新增物品時填 `keys`＝在其他頁面文字中要變成可點連結的名稱（靈石也照使用者要求做成連結）。含有物品名但不是指該物品的詞，加到 `site.js` 的 `STOP`。
  - 不想被自動加上物品連結的區塊加 `data-noitm` 屬性。
